YVON Engine — Task Kanban: How Work Flows

Every flow, end to end: how a chat message becomes a card, how the card gets executed, and how the kanban rebuilds graphs + MemPalace by itself — into the repo, onto GitHub, and into the database.
Design · 2026-08-25 · grounded in cli/task.py, store/tasks/TEMPLATE.yaml, the dashboard, and the VPS graph pipeline BUILT today NEW in this design Partial (demo/wiring exists)
Decision (2026-08-25): work-shaped chat moves to the kanban — chat is the front door, not a second board. Informational chat (questions, facts) never becomes cards; classification is the filter.
No button, no SSH, no 4am session. The heartbeat derives a card each night; the agent runs the scripts detached with logging; the board shows the verified result. Tonight's manual saga becomes a card.

One build → three landing zones

The same card, once executed, writes to the VPS repo clone, pushes to GitHub, and updates the database. All three must agree — that's what the card's acceptance criteria verify.
Honest gap: the sidebar Kanban today reads the Hermes API while the lineage board reads store/tasks/. Phase A aligns them to one source so a card can never exist on one surface and not the other.
