# Migrate Hermes: Hostinger → Contabo

*Plan written 2026-07-31 · Operator: Novy · Applies to repo `main` · Status: **ready to execute***

## 0. Migration model — read this first

This migration is a **fresh re-provision, not a lift-and-shift**. Hermes is rebuilt from
its official installer + the code already in this repo. **No data is copied off the old
Hostinger box.** Consequences:

- Hermes **state.db** (agent sessions, trajectories, in-agent memories) **starts empty** on
  Contabo. YVON's chat history is *not* in state.db — it lives in Supabase (`chat_messages`,
  RLS-scoped) and is unaffected.
- Hermes config (`/root/.hermes/.env`, `config.yaml`) is **recreated** from your API keys.
- The **bearer token** is regenerated by `install.sh`; Vercel's `HERMES_TOKEN` is updated.
- The TLS certificate is re-issued for the new box by certbot.

Why fresh: the old box is 1 core / no swap / disk 80% — it cannot be the source of truth
for a 12 GB / 6-core box, and hand-migrating `state.db` and config is exactly the kind of
"pull VPS data" this plan avoids.

## 3. Step-by-step

### Phase A — before touching the new box (on your Mac, now)

```bash
# 1. Commit the migration push (runbook + code tweaks already staged)
bash cli/verify-deploy.sh && bash cli/deploy.sh   # gate → push → watch Vercel

# 2. (optional, only if you want old Hermes state) back up BEFORE decommissioning:
ssh root@2.25.189.22 'tar czf /root/hermes-backup.tgz -C /root/.hermes .' 2>/dev/null \
  && scp root@2.25.189.22:/root/hermes-backup.tgz ./hermes-backup.tgz

# 3. (optional) identify what serves port 4201 on the old box:
ssh root@2.25.189.22 'ss -ltnp | grep 4201; ps aux | grep -i 4201 | grep -v grep'
```

> Steps 2–3 are **optional and VPS-data-aware** — they only *read* the old box if you choose
> to. The migration does not depend on them.

### Phase B — provision Contabo

```bash
ssh root@169.58.107.148   # fresh Ubuntu 22.04+ (Python 3.11+ preinstalled or apt it)

# baseline
apt-get update -qq && apt-get install -y -qq python3-venv python3-pip git nginx certbot python3-certbot-nginx
```

### Phase C — install Hermes itself (the runtime the wrapper imports)

```bash
# 1. Official installer (same one cli/yvon.js cites). VERIFY this URL first — see §1.
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

# 2. Confirm AIAgent lands where the wrapper expects:
ls -la /usr/local/lib/hermes-agent/run_agent.py || echo "set HERMES_HOME to the real path"

# 3. Recreate Hermes config from YOUR keys (never committed to git):
mkdir -p /root/.hermes
#   /root/.hermes/.env        ← ANTHROPIC_API_KEY=… · DEEPSEEK_API_KEY=…
#   /root/.hermes/config.yaml ← deepseek-v4-pro profile, skills, tools, MCP

# 4. Start Hermes's own API server on 127.0.0.1:9119 (powers the /api/hermes/* proxy):
hermes dashboard &   # confirm: curl -s http://127.0.0.1:9119/openapi.json | head
```

### Phase D — deploy the YVON wrapper

```bash
# DNS already repointed (BigRock) — confirmed: hermes.yvon.in → 169.58.107.148
dig hermes.yvon.in +short    # must return 169.58.107.148 before continuing

# Then deploy (from this repo, on the new box):
git clone https://github.com/OfficialNovizio/YVON-Agentic-OS-.git && cd YVON-Agentic-OS-
cd vps-scripts/yvon-hermes-http && bash install.sh
# install.sh: venv + deps → NEW bearer token → systemd → nginx → certbot TLS → smoke tests
# NOTE the printed token — you'll paste it into Vercel in Phase E.
```

### Phase E — switch Vercel

1. Vercel → `yvon-agentic-os` → Settings → Environment Variables
2. Set `HERMES_TOKEN` = token printed by `install.sh` (Production **and** Preview)
3. Confirm `HERMES_URL=https://hermes.yvon.in` and `VPS_METRICS_URL` point at the metrics domain
4. Trigger a redeploy of the dashboard so the new env takes effect

### Phase F — verify (every surface, from your Mac)

```bash
curl -s https://hermes.yvon.in/healthz                                  # {"ok":true,…}
curl -N -X POST https://hermes.yvon.in/v1/chat/stream \
  -H "Authorization: Bearer <NEW_TOKEN>" -H "Content-Type: application/json" \
  -d '{"message":"hi in one sentence","user_id":"test","room_id":"test"}'   # SSE tokens → done
curl -s "https://<metrics-domain>/metrics/all" | head                     # ventures-health data

# Dashboard in a real browser (quinn's gate):
#   login → /chat → send a message → real agent replies, streaming
#   /office, /foundry/*, Task Board → live via the /api/hermes/* proxy
#   hardware/ventures-health → metrics show a score, not "offline"
bash cli/verify-deploy.sh                                                # still 8/8
```

### Phase G — decommission (after ≥ 1 week of green)

- Keep Hostinger as rollback for one week.
- Then: cancel Hostinger, delete the A records pointing at it, remove the backup tarball if
  taken, rotate anything that touched the old box.

## 4. Rollback (how to abort cleanly)

| Moment | Rollback |
|---|---|
| After DNS flip, before Vercel token swap | Point DNS back to Hostinger; old box still serves |
| After Vercel token swap | Restore old `HERMES_TOKEN` in Vercel + repoint DNS back |
| After decommission | Restore from the Phase-A backup tarball onto a new box |

Keep the old `HERMES_TOKEN` and the backup tarball until the decommission week is over.
