## Standard Sequencing Patterns

### Pattern A — Annual Risk Cycle (all 4 agents)

**Trigger:** annual risk cycle / risk-appetite refresh / KRI recalibration.

**pilot sequences:**

1. **hazard `risk-identification-taxonomy`** — refresh risk register + owner
   assignment
2. **hazard `risk-assessment-quantification`** — quantify per Hubbard/FAIR;
   fat-tail-first per pilot Taleb discipline
3. **pilot `tail-risk-scanning`** — emerging-risk horizon + cognitive-bias
   audit + fragility assessment
4. **pilot `risk-appetite-framework`** — LOAD-BEARING quantified appetite
   statements + board approval
5. **hazard `risk-treatment-strategies`** — MATA per prioritized risks +
   LOAD-BEARING material-risk operator + counsel sign-off
6. **hazard `risk-monitoring-and-audit`** — KRI monitoring + LOAD-BEARING
   audit-trail integrity + three-lines coordination with sentinel
7. **pilot `risk-committee-and-reporting`** — LOAD-BEARING board-level
   quarterly reporting + KRI dashboard
8. **shield coordination** — resilience risks integrated into hazard treatment
9. **prism coordination** — ESG risks integrated into hazard identification
10. **beacon** — material risk investor comms (Reg FD)

### Pattern B — Crisis Scenario Planning + Tabletop

**Trigger:** annual scenario refresh OR post-real-event OR high-priority
scenario need.

**pilot sequences:**

1. **pilot `crisis-scenario-planning`** — driving-force + scenario
   construction (3-5) + narrative + LOAD-BEARING no-fabricated-probabilities
   antifragile response options
2. **hazard `risk-identification-taxonomy`** — scenarios feed identified-risk
   register
3. **hazard `risk-assessment-quantification`** — scenario impact
   quantification
4. **shield `business-continuity-planning`** + **`disaster-recovery-planning`**
   + **`operational-resilience-testing`** — LOAD-BEARING tabletop exercise
   integrating BCP + DR + severe-but-plausible scenarios
5. **warden + veil + bastion** (Cybersecurity) — cyber-scenario coordination
6. **beacon `crisis-comms`** — crisis-comms response coordination
7. **After-Action Review** — corrective action tracker; feed back to hazard
   monitoring + pilot committee reporting

### Pattern C — ESG Reporting Cycle (annual)

**Trigger:** annual ESG report + investor + regulator disclosure cycle.

**pilot sequences (prism-heavy):**

1. **prism `esg-materiality-assessment`** — LOAD-BEARING double-materiality
   assessment + board approval + annual refresh
2. **prism `carbon-accounting-and-reporting`** — LOAD-BEARING Scope 1+2+3
   inventory with cited methodology + CDP/TCFD/IFRS S2 alignment
3. **prism `social-impact-metrics`** — LOAD-BEARING aggregate-only social
   metrics (coordinate hire + maslow + merit + grove for HR data source)
4. **prism `governance-disclosure`** — LOAD-BEARING counsel review before
   publication + SOX/DGCL/ISS/Glass Lewis alignment
5. **shield `third-party-risk-management`** — supplier ESG assessment feeds
   prism social + governance
6. **pilot** — ESG risks integrated into risk-appetite + tail-risk framework
7. **hazard** — ESG-adjacent risks in enterprise risk register
8. **beacon `investor-cadence`** — ESG report published to investors (Reg FD
   for material) + material ESG restatement discipline
9. **herald `press-kit`** — external ESG announcement
10. **operator + counsel + third-party assurance** — final gate before
    publication

### Pattern D — Operational Resilience Event

**Trigger:** BCP activation OR DR failover OR vendor incident OR resilience
testing tolerance breach.

**pilot sequences (shield-heavy):**

1. **shield `operational-resilience-testing`** — IBS impact tolerance breach
   detected → activate response
2. **shield `business-continuity-planning`** — BCP activation per tier
3. **shield `disaster-recovery-planning`** — DR failover per RTO/RPO
4. **shield `third-party-risk-management`** — vendor coordination if third-
   party-triggered
5. **warden + veil + bastion** — cyber technical execution if cyber-triggered
6. **beacon `crisis-comms`** — crisis-comms per Fink 5-stage lifecycle
7. **beacon `investor-cadence`** — Reg FD if material (public companies)
8. **pilot `crisis-scenario-planning`** — After-Action Review integrated
   with future scenarios
9. **hazard `risk-monitoring-and-audit`** — event logged; corrective action
   tracked
10. **canopy + operator + regulator** — regulatory reporting per jurisdiction
    (BoE / FCA / DORA / SEC / etc.)

### Pattern E — Material Risk Investor Comms (Reg FD)

**Trigger:** material risk detected (tail-risk / scenario / resilience event
/ ESG restatement) requiring investor disclosure.

**pilot sequences:**

1. **pilot `tail-risk-scanning` OR pilot `risk-committee-and-reporting` OR
   prism `governance-disclosure` OR shield `operational-resilience-testing`**
   — material risk identified
2. **operator + securities counsel + CFO** — Reg FD materiality assessment
   (LOAD-BEARING legal fence per Universal Principle 5)
3. **beacon `investor-cadence` Phase 4** — material-info trigger detection
   + simultaneous public disclosure protocol
4. **beacon `data-room-discipline`** — supporting materials tagged and
   access-tiered
5. **hazard `risk-monitoring-and-audit`** — event logged
6. **pilot `risk-committee-and-reporting`** — board notified per fiduciary
   responsibility
7. **Coordinate signal `internal-cadence`** — internal comms per stakeholder-
   sequencing (per beacon crisis-comms Phase 4)
8. **Post-disclosure**: 1:1 investor Q&A per beacon `investor-cadence`
   discipline; document Reg FD compliance
