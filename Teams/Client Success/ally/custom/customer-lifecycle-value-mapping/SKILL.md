# Customer Lifecycle Value Mapping

## Introduction

This skill packages customer lifecycle value-mapping discipline for ally —
maps value-realization milestones across the customer lifecycle stages
(onboarding → adoption → maturity → renewal → expansion → advocacy) with
per-stage value definitions grounded in Mehta 2016 + Kaplan & Norton
Balanced Scorecard applied to CS + Bhatt/Chinnappa 2018 + TSIA value-
realization benchmarks.

**Scope distinction:** value-realization framing distinguishes this from
generic journey-mapping (customer-experience touchpoints without value
framing). ally maps CUSTOMER-BUSINESS-VALUE realized per stage — not just
UX-touchpoints.

Custom Route D per §8.2 — cited rubric grounded in canonical CS + strategy
corpus.

## Purpose

Prevents six failure modes:

1. **Value claims without milestone evidence.** Claiming value to customer
   without cited milestone completion = customer trust damage on next
   renewal / QBR / reference request. LOAD-BEARING per Principle 1.
2. **Journey-mapping without value framing.** Touchpoint mapping is UX
   scope; value mapping is CS scope. Confusion = neither properly done.
3. **Stage-agnostic value definitions.** Onboarding-stage value differs
   materially from maturity-stage value differs from expansion-stage value.
   Per-stage definitions required.
4. **Gap identification without intervention design.** Identifying value
   gaps without corresponding intervention plan = observation without action.
5. **Cross-agent handoff opacity.** Onboarding-stage gaps route to kickoff;
   renewal-stage gaps route to retain. Handoffs must be explicit + timely.
6. **Individual crisis DURING lifecycle-mapping conversation.** HARD BOUNDARY.

ally uses this skill as strategic-view companion to `customer-health-scoring`
(operational metric) — both feed QBR + renewal / expansion decisions.

## When to Use

Trigger on:

- "Lifecycle map for [customer/segment]" / "customer maturity assessment"
- "Value realization for [customer]" / "value-delivery evidence for [customer]"
- "Milestone tracking for [stage]" / "value gaps in [lifecycle stage]"
- "Stage-specific value for [tier/segment]"

Do NOT use for:

- **Operational health scoring** → `customer-health-scoring` (ally sibling)
- **UX-touchpoint journey mapping** → Product (ux / loom) or Brand Studio
- **Onboarding-stage execution** → kickoff siblings
- **Renewal / expansion execution** → retain siblings
- **Support-stage execution** → keel siblings
- **Individual mental-health crisis** → HARD BOUNDARY per Universal Principle 3

## Structure / Protocol

Combines lifecycle-stages + value-definitions + milestones + gaps +
intervention:

```
LIFECYCLE STAGES (Mehta 2016 canonical framing)

  1. ONBOARDING            (deployment + initial setup + first value)
  2. ADOPTION              (usage-depth + user-breadth + feature-uptake)
  3. MATURITY              (business-outcome + ROI + strategic-value)
  4. RENEWAL               (renewal decision + terms + expansion-ready)
  5. EXPANSION             (upsell + cross-sell + multi-product / multi-team)
  6. ADVOCACY              (references + case-studies + community)

  Note: not linear — customers can cycle back (e.g., new-product-launch
  triggers new adoption stage; new champion triggers new onboarding).


PER-STAGE VALUE DEFINITIONS (Kaplan/Norton Balanced Scorecard applied to CS)

  Value dimensions per stage:
    - FINANCIAL       (measurable business impact — cost saved / revenue
                       gained / margin improved)
    - CUSTOMER        (their customer outcomes — support / satisfaction /
                       retention improvement)
    - INTERNAL        (operational efficiency / cycle-time / quality)
    - LEARNING/GROWTH (capability building / process improvement)

  Onboarding stage: primarily internal + learning-growth value
  Adoption stage: internal + customer value
  Maturity stage: financial + customer + internal (full Balanced Scorecard)
  Renewal stage: financial + customer (renewal justification)
  Expansion stage: financial + strategic + growth
  Advocacy stage: strategic value to org (references / community)


MILESTONE COMPLETION EVIDENCE (LOAD-BEARING discipline)

  Every value claim requires cited milestone-completion evidence:
    - Data points (usage / outcome metrics)
    - Customer testimonials + quotes (attributable, sourced)
    - Case-study documentation
    - Support-ticket resolution patterns
    - Executive-sponsor confirmations

  Never claim value without milestone completion evidence.


LIFECYCLE-VALUE-MAPPING OPERATIONAL SEQUENCE (this skill's phase-by-phase):

  Phase 1: LIFECYCLE-STAGE CONFIRMATION                 (which stage per customer / segment)
  Phase 2: PER-STAGE VALUE DEFINITIONS                   (Balanced-Scorecard-adapted)
  Phase 3: MILESTONE COMPLETION EVIDENCE SOURCING        (LOAD-BEARING)
  Phase 4: GAP IDENTIFICATION + INTERVENTION DESIGN      (per gap → owner + timeline)
  Phase 5: CROSS-AGENT HANDOFFS                          (kickoff / retain / keel per stage)
```

## Instructions

### Phase 1 — Lifecycle-stage confirmation

Per customer or segment:
- Confirm current stage (onboarding / adoption / maturity / renewal /
  expansion / advocacy)
- Confirm stage-transition dates (when did customer transition)
- Note non-linear cycles (new-product-launch triggering new adoption stage)

### Phase 2 — Per-stage value definitions

Apply Balanced Scorecard dimensions per stage:
- Financial value expected
- Customer-outcome value expected
- Internal-efficiency value expected
- Learning/growth value expected

Weight per stage (onboarding weights different dimensions than maturity).

### Phase 3 — Milestone completion evidence sourcing (LOAD-BEARING)

Per value definition:
- Cite completion evidence (data / testimonial / case study / ticket
  resolution / exec confirmation)
- If evidence unavailable, flag milestone as INCOMPLETE — do NOT claim value

**Never value claim without evidence.** LOAD-BEARING per Principle 1.

### Phase 4 — Gap identification + intervention design

- Gaps = expected-stage-value NOT realized per evidence
- Per gap: owner + intervention + timeline
- Coordinate with kickoff (onboarding-stage gaps) + retain (renewal /
  expansion-stage gaps) + keel (support-stage gaps)

### Phase 5 — Cross-agent handoffs

- Onboarding-stage gaps → kickoff `time-to-first-value-optimization`
- Adoption / maturity gaps → ally `qbr-executive-review-framework` for
  executive escalation
- Renewal-stage gaps → retain `renewal-negotiation`
- Expansion-stage gaps → retain `expansion-motions`
- Support-stage gaps → keel `support-analytics`

## Output Format

- **Lifecycle-stage map** per customer / segment with stage transitions
- **Per-stage value-definition matrix** with Balanced-Scorecard dimensions
- **Milestone completion evidence log** per value claim
- **Gap identification + intervention plan** per gap
- **Cross-agent handoff briefs** to relevant siblings

## Principles

1. **Never value claims to customer without milestone-completion evidence** —
   LOAD-BEARING per Purpose failure mode 1.
2. **Journey-mapping vs value-mapping distinction** — this skill is
   VALUE-mapping, not UX-touchpoint mapping.
3. **Per-stage value definitions** — no stage-agnostic value framing.
4. **Balanced Scorecard dimensions applied** — financial + customer +
   internal + learning/growth per stage weights.
5. **Gap identification maps to intervention design** — no observation
   without action.
6. **Cross-agent handoffs explicit** — owner + timeline per handoff.
7. **No fabrication** — cited institutional + practitioner sources. Universal
   Principle 1.
8. **Aggregate-only at publication surface** — Universal Principle 2.
   Individual customer value stories require customer sign-off before
   external publication (press / case study / investor).
9. **Individual crisis HARD BOUNDARY** — Universal Principle 3 inherited.
10. **§0.6 flag.** Sources Tier B. Downgrade path in `logical/README.md`.

## Fallback

- **Milestone evidence unavailable** for expected value claim. Flag milestone
  INCOMPLETE. Do NOT claim value. Coordinate with customer + CSM for
  evidence sourcing.
- **Customer refuses reference / case-study participation** in advocacy
  stage. Respect refusal — do NOT publish without explicit sign-off per
  Principle 8. Coordinate with retain `customer-advocacy` for alternative
  advocacy channels.
- **Cross-agent handoff ambiguity** (which sibling owns intervention).
  Route to ally + operator for scope clarification.
- **Individual crisis signal during lifecycle-mapping conversation.** STOP.
  Route per Universal Principle 3 (inherited) to manager + HR Ops + EAP.
