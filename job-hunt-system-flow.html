YVON Job Hunt — Whole System Flow

The complete pipeline: profile → multiple resumes → finding companies → applying → tracking — with the logic flow, the fallbacks, and what's built vs planned. Grounded in the codebase as of 2026-08-25.
Design · grounded in migrations 121–131, lib/job-hunt/*, vps-scripts/fetch-*.py BUILT today NEW / planned PARTIAL (analysis exists, pipeline doesn't)
One funnel: everything flows one direction — profile feeds scoring and materials, sync feeds postings, postings feed Companies, Companies feeds applications, applications feed the tracker, and the kanban owns the 3×-daily sync as a recurring card. Nothing is a side pipeline.

Logic flow with fallbacks

Every decision node has a fallback branch — a failed source, a missing key, a block, a duplicate, a closure, an empty profile. Nothing dead-ends.
flowchart TD
  START([Start]) --> PROF{Profile setup?}
  PROF -- "no / incomplete" --> IMP["Import-first: resume upload / LinkedIn export"]
  IMP --> PROF
  PROF -- "yes" --> SCORING["Fit weights: Technical 30 / Exp 25 / Beh 15 / Career 30"]
  SCORING --> SYNC["3x daily sync (kanban TS-REC-003)"]
  SYNC --> SRC["Sources: Adzuna + Indeed + LinkedIn + RemoteOK + Remotive"]
  SRC --> KEY{"Adzuna key set?"}
  KEY -- "no" --> BOARDS["Boards still run; log says why"]
  BOARDS --> FETCH
  KEY -- "yes" --> FETCH["Fetch newest page only (delta window)"]
  FETCH --> BLOCK{"CAPTCHA / rate limit?"}
  BLOCK -- "yes" --> SKIP["Skip + log, other queries continue"]
  SKIP --> FETCH
  BLOCK -- "no" --> DEDUP["Dedup: UNIQUE(source, external_id) — insert-only"]
  DEDUP --> NEWP{"New postings?"}
  NEWP -- "no" --> STALE["Closed sweep: missing N runs / URL 404 → status=closed"]
  NEWP -- "yes" --> UPSERT["Upsert into job_postings (status=discovered)"]
  UPSERT --> STALE
  STALE --> SCORE2["Fit score each posting (profile weights)"]
  SCORE2 --> VETO{"Deal-breaker hit?"}
  VETO -- "yes" --> VETOED["Marked 'vetoed' with reason — visible, not hidden"]
  VETOED --> COMP
  VETO -- "no" --> COMP["Companies page: Hiring now (from postings) + watchlist + BC directory"]
  COMP --> QUEUE["Queue postings worth applying to"]
  QUEUE --> MAT["Tailor: cover letter + resume variant from profile"]
  MAT --> HUMAN{"Human review & approval"}
  HUMAN -- "no" --> QUEUE
  HUMAN -- "yes" --> APPLY["Apply on the real site (never auto-submitted)"]
  APPLY --> TRACK["Tracker: applied → interview → offer / rejected"]
  TRACK --> FOLLOW["Follow-up drafts after 10 days of silence (drafts only)"]
  FOLLOW --> START
Read it as a circuit: the loop at the bottom (track → follow-up → profile) is the "keep the search alive" cycle; every dashed decision is a fallback. The whole thing is human-in-the-loop — nothing sends, applies, or submits by itself.

The tables, the posting status lifecycle, the sync cadence, and the kanban wiring.

The posting status lifecycle

flowchart LR
  D[discovered] --> Q[queued]
  Q --> A[applied]
  A --> I[interview]
  I --> O[offer]
  I --> R[rejected]
  D -.-> C[closed]
  Q -.-> C
  A -.-> C
  D -.-> ARC[archived]
  Q -.-> ARC
  C -.-> ARC

closed = the posting no longer exists (disappeared from source results for N consecutive syncs, or its URL 404s in the nightly sweep). archived = you dismissed it. Both leave "Hiring now" immediately. closed is a planned schema addition (current CHECK constraint lacks it).

The 3× daily sync (kanban TS-REC-003)

🌅 Morning · 8am PT (15:00 UTC)

Delta fetch: newest page per query per source
Insert-only upserts — duplicates impossible
Closed sweep: mark vanished postings

🌆 Evening · 6pm PT (01:00 UTC)

Same incremental pass — new postings since morning
Fit scores recomputed for new rows
"Hiring now" on Companies refreshes

🌙 Night · 11pm PT (06:00 UTC)

Delta fetch + full closed sweep (URL verification)
Sync card closes on the kanban with counts
New day's search starts clean

Fallbacks, per stage
