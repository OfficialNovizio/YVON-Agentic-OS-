## 1. PROBLEM

`/chat` is the primary surface of the product — the place the 46-agent fleet is actually
operated from — and it carried three problems that are separate but compounded each other.

**A. The design had no system behind it.** `dashboard/DESIGN.md` is explicit that its own tokens
were "extracted from the existing dashboard… not invented," and it carries two unresolved
`<FILL_IN>` markers, including the typeface itself: "Current: Inter — **flagged as overused**;
atlas to select a distinctive replacement (`<FILL_IN>`)." `app/chat/chat.css` had drifted into its
own private palette (`--chat-accent: #6366f1` indigo) that appears nowhere in `DESIGN.md`, whose
stated accent is amber-400. Two documents, two accents, neither authoritative.

**B. Density had been mistaken for craft.** The thread ran at 13px body, 12px agent names,
9.5px timestamps and 8.5px department tags, against `rgba(255,255,255,0.38)` faint text on
`#0a0a0f`. `DESIGN.md`'s own register line — "clarity and density beat decoration" — had been
read as licence for type that is simply too small to read comfortably for the length of a working
session.

**C. Four concrete interaction defects**, each found by reading the pre-redesign source:

1. `Composer.tsx` locked the textarea to `rows={1}` with no auto-grow. Any message longer than a
   line was composed through a single-line letterbox.
2. `MessageStream.tsx` called `endRef.scrollIntoView()` unconditionally on every
   `messages.length`, `awaitingReply` and `streamingText` change — so scrolling up to re-read
   anything during a live turn yanked the reader back to the bottom on the next token.
3. There was no way to stop a running generation from the keyboard; Stop was mouse-only.
4. `LiveStrip.tsx` rendered a permanent "Workforce · all agents idle" row when nothing was
   happening — a line of chrome whose only content was the absence of content.

## 2. EVIDENCE

Direct source inspection and measurement, this session (2026-08-17), against the working tree —
not a docs re-read, not preference.

**On A — the system gap.**
- `dashboard/DESIGN.md` contains the literal string `<FILL_IN>` twice, one of which is the
  product's display typeface.
- `app/chat/chat.css` (pre-redesign) defined `--chat-accent: #6366f1`; `DESIGN.md` §Color names
  amber-400 as the accent. Neither references the other.
- `DESIGN.md` also self-reports "Two current violations flagged for fix" against its own
  no-gray-on-colour rule, unaddressed.

**On C — the interaction defects.** All four are single-line source facts in the pre-redesign
files, cited above in §1.C with the responsible component named. Defect 2 in particular is a
`useEffect` with no "is the reader at the bottom" guard — the behaviour is unconditional by
construction, not intermittent.

**On accessibility — measured, and it found real failures in my own first pass.** Contrast
computed per WCAG 2.1 relative-luminance, not eyeballed. The first version of this redesign
shipped three text colours that **failed AA**, and were corrected before this PRD was written:

| pair | before | after | verdict |
|---|---|---|---|
| faint text (timestamps, `@handles`, counts) on white | `#9a9aa2` — **2.79:1 FAIL** | `#6b6b74` — **5.28:1** | AA |
| same, on paper `#f4f4f1` | 2.53:1 FAIL | 4.79:1 | AA |
| same, on concrete `#f2f2ee` | 2.49:1 FAIL | 4.70:1 | AA |
| success text ("N live", copy-confirm, CAOS checks) | `#7ba800` — **2.82:1 FAIL** | `#587000` — **5.63:1** | AA |
| second success ink (chips, command cards) | `#5f7a00` — 4.92:1 | `#587000` — folded to one | AA |

Passing without change, measured: body charcoal `#353241` on white **12.47:1** (AAA) and on paper
**11.32:1** (AAA); heading plum `#21164c` on white **16.36:1** (AAA); slate smoke `#5f5f69` on
white **6.31:1** (AA); white on the violet bubble **6.44:1** (AA); violet as link text on white
**6.44:1** (AA); error `#b91c1c` on white **6.47:1** (AA).

**Known and accepted below threshold, named rather than hidden:** the pearl-mist hairline
`#e0e0db` on white is **1.32:1**, far under the 3:1 WCAG guidance for meaningful non-text UI
boundaries. This is not an oversight — it is the Adora system's defining move ("depth comes from
white-on-white layering and generous radius, not shadow stacks"), and softening it would dissolve
the design. It is a deliberate trade recorded in §7, and it needs mia's
`ui-accessibility-standards` sign-off, not mine.

Evidence type: source audit + computed measurement. There is no user-research citation here
because no user-demand claim is being made — this is a craft-and-defect gap, and the defects are
empirical.

## 3. PROPOSED SCOPE

Three work items. A and B shipped in this session; C is not started.

**Work item A — adopt Adora as a real, route-scoped design system. (shipped)**

Source: `https://styles.refero.design/style/26a9840f-f128-4cfc-84a5-feb7db1bf577`, an external
reference the operator selected — "impressionist museum behind frosted glass." It resolves both
`<FILL_IN>`s in `DESIGN.md`: General Sans 600/700 for display (the reference's own documented
fallback for PolySans, which is commercially licensed), Plus Jakarta Sans 400–600 for body/UI,
−0.02em tracking applied universally to unify the pair.

New file `dashboard/app/adora.css` holds the whole system: palette, faces, radii (8px controls /
28px cards / 40px frames / 200px stadium), primitives, motion. It ships in two layers — the
existing dark chrome values live in `:root` so nothing that hasn't opted in changes, and the light
gallery lives under `[data-theme='adora']`.

**Route-scoping is the load-bearing decision.** `components/Shell.tsx` sets
`<html data-theme="adora">` only for `ADORA_ROUTE_PREFIXES = ['/chat']`. The dashboard has 40+
other routes built against an obsidian surface; flipping `body` globally would have broken every
one of them in the same commit. Going app-wide later is moving one attribute into `layout.tsx`
and deleting that list — the mechanism is already built, only the switch is scoped.

`app/chat/chat.css` was rewritten with **the same token names and the same class names** as the
old command-deck build (`--chat-text`, `--chat-hairline`, `.chat-glass`, `.chat-scroll`). Only the
values changed. `PipelineHud.tsx` — 30KB, the single largest component on the page — is almost
entirely token-driven, so it moved to the light surface with **four** targeted edits and zero
logic touched. `AttachmentCard`, `AudioRecorder`, `VentureSelector` and `RepoModeToggle` came
across the same way.

**Work item B — the visual and interaction rebuild. (shipped)**

Layout: a floating white pill header (never a full-bleed bar, per the system), a white pill dock
rail, the teams roster and CAOS card as floating 28px-radius gallery cards, the thread on a paper
canvas.

Messages: agent replies became **white gallery cards with the avatar hung off the top-left edge**
and the department as a chromatic stadium tag — a plaque, not a chat bubble. User messages are
filled violet `#592eff`. Streaming carries a cyan→violet→magenta stroke painted across the card's
top edge, matching the caret and the live-strip badge so "generating" reads as one idea across
the page.

Type moved up throughout: body 13px → **14.5px at 1.6 leading**, agent names 12px → 15px display,
timestamps 9.5px → 10px at the now-AA faint colour.

New file `dashboard/app/chat/Atelier.tsx` — three dependency-free pieces:
- `AtelierBackdrop` — pastel oil-paint washes on a 26s drift. The `.chat-shell` element carries
  `data-live`, so during a real turn the washes speed to 11s and lift opacity. Ambient state,
  driven by the same `awaitingReply || pipeline.source === 'live'` that gates the badge.
- `Squiggle` — the system's hand-drawn underline, drawing itself on mount.
- `WorkforceOrb` — a Fibonacci point-sphere of the fleet on a 2D canvas, Y-spun and
  perspective-projected: one point per `FLEET` entry, coloured by its real department tint, and
  agents whose `/api/agent-status` says `active` burn brighter and pulse. No three.js, no image
  files, no bundle cost.

The four §1.C defects, fixed: auto-grow 1→8 rows with snap-back on send; smart autoscroll that
follows only when the reader is already within 80px of the bottom, and otherwise surfaces a "N new
messages" pill with a live unseen count; `Esc` stops an in-flight generation; the idle live-strip
returns `null`.

Added beyond the defect list: per-message copy on hover (keyboard-reachable), consecutive
same-agent messages within 4 minutes grouping under one header, and an empty state that is an
actual invitation — the orb, a display heading with the squiggle, and focus-aware starter prompts
that load into the composer via a `prefill` prop.

**Work item C — propagate to the rest of the dashboard. (not started)**

`Sidebar`/`TopBar`/`Shell` were converted to `--app-*` tokens in this session, so the chrome is
already theme-ready. Every *page* body is not. Ordering, complexity and whether Adora even suits a
dense Kanban or a Recharts surface are open questions — see §4.

## 4. OUT-OF-SCOPE

- **Taking the whole app light.** The mechanism exists (one attribute), the decision does not.
  Every non-`/chat` page was authored against obsidian; some — `/brain`'s graph viewer, the
  pipelines Kanban, anything Recharts — may be *better* dark. That is a per-surface design
  judgement for atlas, and it needs its own PRD with a route inventory. Do not read the existence
  of `ADORA_ROUTE_PREFIXES` as a plan to flip it.
- **Rewriting `dashboard/DESIGN.md` to make Adora the house system.** This PRD documents what
  `/chat` now does. Promoting it from "the token set one route uses" to "the token set the product
  uses" is atlas's call and outranks a redesign ticket. `DESIGN.md`'s `<FILL_IN>`s are answered
  *for this route*; they are still open for the product.
- **Licensing PolySans.** General Sans is in place as the reference's own documented fallback and
  is metrically close. Swapping is one line (`--adora-display`). Whether the licence is worth
  buying is a brand-budget decision, not an implementation one.
- **Migrating shared components off the Material-3 dark classes.** `NotificationsSetup` and
  friends still paint with `text-on-surface`, `bg-primary` and other fixed hexes tuned for
  obsidian. Rather than fork them, `adora.css` carries an explicitly-labelled *legacy-token safety
  net* — 12 scoped overrides that re-point those utilities inside a gallery route. It is a
  deliberate stopgap and it is commented as one, with "delete a line the day its component is
  migrated." Doing that migration properly is Work item C's job.
- **Dead code found but not touched.** `app/chat/PillHeader.tsx`, `app/chat/RoomSwitcher.tsx` and
  `app/chat/AttachmentCard.tsx` are imported nowhere in `app/`, `components/` or `lib/`. Deleting
  them is correct and is not this PRD's business; `AttachmentCard` being unused also implies
  attachments may not render in the thread at all, which is a **separate bug worth its own
  ticket** rather than something to fold in silently here.
- **The pre-existing `border-[var(--chat-accent)]/40` pattern in `PipelineHud`.** Tailwind cannot
  inject an alpha modifier into an arbitrary `var()`. It predates this work and was left alone;
  every var-with-alpha *introduced* by this redesign was replaced with a token carrying its own
  alpha (`--app-bar`, `--app-popover`, `--app-accent-line`, `--app-accent-ring`).

## 7. RISKS + ROLLBACK STANCE

- **Risk: nothing here has been seen running — and this codebase has rolled back a redesign for
  exactly this reason before.** tsc and the CSS compile prove it *builds*; they prove nothing
  about whether it *looks right*, whether the orb paints at the correct DPR, or whether the
  autoscroll guard behaves at real streaming rates. The static HTML preview produced alongside
  this PRD uses the same CSS but is a reproduction, not the app. Treat every §3 claim as
  unverified-at-runtime until Gate 1–5 pass. This is not a generic caveat: §0a cites the
  2026-07-30 redesign, rolled back in full, whose postmortem in `SESSION-HANDOUT.md` §5.1 names
  "verified via compiled CSS and tsc, app never opened" as the specific failure. Same method,
  same codebase, five weeks earlier.
  **Mitigation:** Gate 0's new browser-verification line, plus Gate 2, are cheap and should be
  run before anything is committed. reticle and Playwright are both already installed for this
  exact purpose (§0a) and currently wired to nothing (`SESSION-HANDOUT.md` §8 E5, still open) —
  using either here would also be a real step toward closing E5 for the whole codebase, not just
  this route.

- **Risk: the hairline is below WCAG's non-text threshold (1.32:1).** Card edges, dividers and
  input borders may be genuinely hard to see for low-vision users or on a dim/low-quality panel.
  This is inherent to the chosen system, not a bug in the implementation.
  **Mitigation options, in order of preference:** (a) darken `--chat-hairline` to ~`#c9c9c2`
  (≈1.9:1 — better, still short) only where a border is load-bearing, keeping pearl for purely
  decorative dividers; (b) accept and document as a known limitation with atlas's sign-off;
  (c) reject Adora's elevation model for this surface. **This is not my call and I have not made
  it.**

- **Risk: two external font CDNs are now on the critical render path** — Fontshare (General Sans)
  in addition to the Google Fonts already imported. A Fontshare outage degrades display type to
  Plus Jakarta, then to system sans. Non-fatal by construction, but it is a new third-party
  dependency for a surface the business runs on.
  **Mitigation:** self-host both faces in `public/fonts/` before this is considered production-
  hardened. Not done.

- **Risk: the legacy-token safety net is a specificity hack.** The 12 `[data-theme='adora']`
  overrides in `adora.css` win on specificity (0,1,1 vs 0,1,0), which is stable — but it means a
  shared component can look correct inside `/chat` while remaining un-migrated, which quietly
  removes the pressure to fix it properly. It is commented as a stopgap for exactly this reason.
  **Mitigation:** Work item C, or a lint rule that fails on new `text-on-surface` usage.

- **Risk: `next build` was never completed on this change.** A CSS `@import` of a local file
  through Next's PostCSS chain is well-supported and was verified compiling standalone, but
  "compiles under the Tailwind CLI" is a weaker claim than "compiles under Next's loader."
  **Mitigation:** Gate 0. This is the highest-probability place for an unpleasant surprise.

- **Rollback: complete and trivial.** Every change is a working-tree edit against a clean `main`
  (verified clean before the first write; last commit `20c327d`). Nothing was committed, no
  migration was applied, no schema, API route, SSE contract or data path was touched — this is a
  presentation-layer change end to end.

  ```
  git checkout -- dashboard/app dashboard/components dashboard/tailwind.config.ts
  rm -f dashboard/app/adora.css dashboard/app/chat/Atelier.tsx
  ```

  Partial rollback is also available and is the better move if only the light surface is the
  problem: delete `'/chat'` from `ADORA_ROUTE_PREFIXES` in `components/Shell.tsx`. The layout,
  the composer auto-grow, the autoscroll guard, `Esc`-to-stop and the message grouping all survive
  that, because they are structural rather than chromatic. The page would render the new
  structure against dark tokens — untested, and not a state anyone has looked at, but it is one
  line and it isolates "I don't like the light theme" from "the interaction changes are wrong."
