04 Three ways to build the flow

OPTION A Evidence-first turn — one agent, fast

One turn does everything: scrape → persist → render → ask. You steer after seeing evidence. Fastest path to your target sentence; the agent holds the whole job.
You
"build like <URL>" → sees screenshots + data inline → "adapt it to Novizio" → Yes on proposal → task born with evidence
Agent (mia)
scrape reference◐ → save artifacts to workspace○ → emit evidence (images + data)○ → ask: clone or adapt? → proposal carries artifacts[]○
Wrapper
stream phase + tool events● → strip proposal block○ fix needed → emit task.proposed + artifacts◐
Chat UI
evidence cards (screenshot + data table)○ → Yes/No proposal card● → artifact links on the task○
Pros: closest to your sentence — one message in, evidence out, question asked. Cons: one agent self-scopes a big turn (the test's cost problem); gate stays soft unless paired with the unlock button. Covers: S1 S3 S4 S5 S6 S7 (S2 via sticky routing, no fleet).

OPTION B Two-phase, gate kept — today's design, made real

Turn 1 produces the scrape report and stops — wrapper enforces read-only tools in discussion-only rooms. Your reply (one click) unlocks phase 2, which ends in the proposal. Same shape as the rail intends; every gap fixed.
You
"build like <URL>" → scrape report + clone/adapt question → clicks Approve & execute (inline) → Yes on proposal → task born with evidence
Agent (mia)
turn 1: scrape → artifacts → evidence → ask○ build → HARD STOP (read-only tools only) → turn 2: direction → proposal w/ artifacts
Wrapper
enforce gate: block terminal/write tools when unlocked_at is null○ decision → one-click unlock flips execution_unlocked_at○ → strip fix + artifacts[] on proposal○
Chat UI
evidence cards + unlock button○ → Yes/No card● → artifact links on task○
Pros: the stall you hit becomes impossible — the agent physically cannot run 24 unrestricted calls while "discussion-only"; every turn is cheap. Cons: two turns minimum; needs the gate decision made (enforce vs one-click). Covers: all of A's scenarios, plus S2 stays single-agent unless C is added later.

OPTION C Orchestrated fleet — no mention needed

The truest-to-rail shape: no mention → meta sequences mia (scrape/review) and spark/atlas (directions) in parallel; you pick a direction; dev sequences the build task. Slowest, most expensive, most "YVON".

"build me a website like this" — no @mention → evidence from mia + directions from spark/atlas → pick a direction → task via dev-sequenced proposal

Pros: the no-mention case becomes the showcase — fleet behavior, design directions to choose from. Cons: everything A/B need, plus delegation plumbing and multi-lane UI; orchestrator loops are a new failure class; 3× the turns. Covers: S2 properly; all others.

06 Recommendation & the calls only you can make

Recommended: B's gate + A's evidence turn — C later

Build the six shared pieces first (they're option-independent), ship the flow as Option B — a Phase-1 turn that shows before it asks (screenshots + data inline, then the clone/adapt question), a gate that's actually enforced, and a task proposal born with its evidence. That delivers your target sentence on the current two-turn shape. Option C (no-mention fleet) then becomes an increment — meta delegation on top of working evidence rails — instead of a rewrite. Building C first would fail the same way the test did, because its evidence rails don't exist yet.

Suggested build order: ① strip fix (smallest, unblocks tasks today) → ② artifact store + image path (the critical path) → ③ scrape backend verified → ④ reference-first contract → ⑤ gate decision implemented → ⑥ proposals carry artifacts[] → ⑦ (later) meta delegation for C.

Three decisions to sign off

  1. Clone vs adapt — when you say "like this", is exact-clone ever the goal, or is it always "adapt to the venture"? (Decides whether Phase 1 ends in a comparison question or a direction proposal.)
  2. Where evidence lives — chat-only previews, or a per-task artifact drawer you can reopen weeks later? (Decides how much of the artifact store to build.)
  3. Gate philosophy — enforce discussion-only (agents physically can't execute), or one-click "Approve & execute" unlock anywhere? (Decides the wrapper change.)
