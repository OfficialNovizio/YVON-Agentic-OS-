Fix DB-venture workspaces: novizio had no chats/tasks visible

Follow-on from the previous crash fix, which stopped the crash but was WRONG:
falling back to WORKSPACE_MAP[DEFAULT] silently switched every DB-venture user
onto the yvon-os workspace, hiding their own content.

Established facts: ventures = novizio / yvon-os / hourbour, and chat_rooms holds
16 rooms with venture_slug='novizio' (all active, none archived). So the data was
always there - it was never being shown.

Two causes:

1. WORKSPACE_MAP (lib/workspaces.ts) contains ONLY 'yvon-os'; real ventures come
   from the DB via /api/ventures. WorkspaceContext now BUILDS a Workspace from the
   live venture list when the key is a DB slug, instead of collapsing to the
   default. This is what actually makes novizio's rooms and tasks visible again.

2. syncVentureCookie only wrote yvon_active_venture when the static map entry had
   a ventureSlug - and yvon-os has none, so the cookie was never set for ANY DB
   venture. resolveVentureSlug() therefore never scoped the rooms/tasks APIs to
   the active venture; they kept answering for the wrong one. A DB venture's key
   IS its slug, so the cookie now falls through to `key`.

Typecheck clean.
